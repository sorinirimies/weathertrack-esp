# esp32-c6-weathertrack — AI Agent Rules

## Project Overview

ESP32-C6 weather station with a 320×172 ST7789 LCD. Two UI implementations
(TUI + GUI) share a common core library. Uses OpenMeteo API (no key required).

## Architecture

Cargo workspace with three crates:

| Crate | Role |
|-------|------|
| `weathertrack-core` | Shared logic: types, Elm state (Model/Msg/update), API parsing, WMO codes, weather cache. Platform-agnostic. |
| `weathertrack-tui` | ESP32-C6 Ratatui + mousefood TUI. FONT_10X20, 32×8 grid. Excluded from workspace. |
| `weathertrack-gui` | ESP32-C6 Slint GUI with software renderer + line-by-line platform adapter. Excluded from workspace. |

### Elm Architecture (Model → Msg → update)

- **Model** lives in `weathertrack-core/src/app.rs` — single source of truth
- **Msg** enum: `NextPage`, `WeatherLoaded(Box<Forecast>)`, `WeatherError(String)`, `LocationDetected`
- **update()** is a pure state transition — no I/O, no side effects
- Both TUI and GUI import `weathertrack_core::app` — never duplicate state logic

### Module Structure (both TUI and GUI)

```
src/
├── main.rs      — entry point, hardware init, Elm event loop
├── hal.rs       — LED, WiFi, NVS, SD card (hardware abstraction)
├── net.rs       — HTTP client, weather/geolocation fetch
└── ui/ (TUI)    — view dispatcher + screen modules
    or
├── platform.rs (GUI) — Slint platform adapter + line renderer
├── bridge.rs (GUI)   — core types → Slint types
```

### Slint UI Structure (GUI)

```
ui/
├── weather.slint              — entry point (imports only)
├── types.slint                — WeatherData, ForecastDay, AlertData
├── components/spinner.slint   — LoadingSpinner
├── pages/hero.slint           — CurrentPage (merged hero + details)
└── pages/forecast.slint       — ForecastDayPage (one day per page)
```

## Rules

### Code Organization
1. **All shared logic in `weathertrack-core`** — types, parsing, Elm state, cache, constants.
2. **Core must NOT depend on UI or ESP32 crates** — no ratatui, slint, esp-idf, embedded-graphics.
3. **No code duplication between TUI and GUI** — if both need it, it belongs in core.
4. **Shared constants** (`FORECAST_DAYS`, `REFRESH_MS`) live in `weathertrack-core/src/lib.rs`.

### State Management
5. **All state changes go through `app::update(model, msg)`** — never mutate Model directly.
6. **Use `Msg::LocationDetected`** for geolocation results — don't bypass the Elm loop.
7. **`model.dirty = true`** must be set in every Msg handler that changes visible state.
8. **`Box<Forecast>`** in `Msg::WeatherLoaded` to avoid large enum variant (clippy).

### Build & Quality
9. **Use `just` for all tasks** — `just build-tui-release`, `just run-gui-release`, etc.
10. **`just gen-sdkconfig`** must run before ESP32 builds (auto-runs via task deps).
11. **WiFi credentials from `config.toml`** (gitignored) — never hardcode. Template: `config.toml.example`.
12. Run before committing:
    - `cargo fmt --all`
    - `cargo clippy -p weathertrack-core --all-targets --all-features -- -D warnings -A deprecated`
    - `cargo test -p weathertrack-core --all-features --all-targets`
13. **No `mut` captures in Nushell closures** — use `each` + `filter` + `complete` patterns instead.

### Hardware
14. **Display**: ST7789 172×320, rotated 90° → 320×172 landscape. SPI at 40MHz.
15. **LED**: WS2812 on GPIO8 (GRB format — note the swap in `set_led`).
16. **Button**: BOOT on GPIO9 (active low).
17. **SD card**: Optional, detected at `/sdcard` mount point.
18. **Partition table**: Custom 8MB with ~7.9MB app partition. Generated by `just gen-sdkconfig`.

### Git & Remotes
19. Three remotes: `origin` (Gitea 192.168.1.204), `starscream` (Gitea 192.168.1.44), `github`.
20. Use `just push-all` to push to all. Continue-on-failure pattern.
21. **Git LFS** for images: `.png`, `.jpg`, `.gif`, `.svg`, `.pdf`, etc.
22. **sdkconfig.defaults is gitignored** — machine-specific, generated by `just gen-sdkconfig`.

### Conventions
23. Use `anyhow::Result` for fallible operations.
24. Commit messages: conventional commits (`feat:`, `fix:`, `refactor:`, `chore:`, `ci:`, `docs:`).
25. Nushell scripts use `def main [] {}` entry point and immutable functional pipelines.
